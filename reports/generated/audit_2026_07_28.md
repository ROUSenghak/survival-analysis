# Repository audit and full regeneration — 2026-07-28

Scope: the whole repository, with the synthetic-benchmark pipeline as the focus.
Everything below was verified by running it, not by reading it.

---

## 1. What was inspected

Every tracked file outside `.venv/`: the `src/boamp` package (10,013 lines across
54 modules), all 12 notebooks, 23 scripts, both config trees, the raw and derived
data, 83 calibration tables, the synthetic-benchmark artifact tree, all figures,
run logs, four LaTeX sources with their PDFs, and the four markdown design
documents.

## 2. Problems found

### 2.1 Release-blocking: the published benchmark no longer replayed

`tests/test_synthetic_reproducibility.py::test_released_benchmark_replays_from_recorded_configuration`
failed. Six of nine released tables — `latent_buyers`, `latent_needs`,
`latent_cycles`, `clean_notices`, `observed_notices`, `corruption_log` — did not
reproduce from their recorded seeds and configuration.

Diagnosis: **not** generator drift. Every differing value was a float differing
in the last one or two units in the last place (`8.2867827783483605` versus
`8.2867827783483623`), in columns fed by `rng.beta`, `rng.lognormal`, and
`raw / raw.sum()`. Counts, identities, and column sets were identical
throughout. The cause is that NumPy's generator and reduction kernels are
bit-stable per build, not across builds, and `requirements.txt` pinned nothing
tighter than `numpy>=2.0`.

Independently, the released artifacts recorded a calibration-corpus hash
(`e0df5cb916ac96c1` for `data/interim/boamp_common_prepared.csv`) that the
current pipeline does not produce. Rebuilding that file from raw yields
`b8bb2eb0089165c2` — the same hash the v0.2 artifacts recorded. The v0.3
artifacts had therefore been calibrated against a corpus state that no longer
existed.

### 2.3 Documentation contradicting the code

- `config/synthetic/scenarios/central_provisional.yaml` described its scoped
  block as "0.02/0.25 with near-window share 0.80" while the file set
  0.102/0.74 with near-window share 1.00.
- `config/pipeline.yaml` claimed "~88% of sources are imputed"; the measured
  rate is 82.7%.
- Notebook 01 and notebook 04 referred to a 3,159-source population; it has been
  3,380 since the two-layer restructure, as `docs/methodology.md` already said.
- `docs/synthetic_benchmark_dgp_specification.md` quoted a true-gap mean and
  Monte Carlo interval that the current run does not produce.
- The README's reproduction recipe ran the central sweep script *before* the
  replicate generator. Both write `central_provisional/world_001`, and only the
  sweep script records the parameter-selection provenance — so the documented
  order destroyed it. The released `world_001` metadata indeed had no
  `candidate_revision` key.

### 2.4 Defects in the tooling itself

- `scripts/build_benchmark_registries.py` wrote a **running counter** into
  `scenario_manifest.csv#generated_replicates_for_scenario`, a column whose name
  promises a scenario-level total. Row 1 of a 10-seed scenario read `1`.
- The registry recorded zero `ALGORITHM_PARAMETER` rows although the DGP
  specification documents that class as populated: production linkage settings
  were never registered.
- `scripts/verify_dirty_state_overlay_archive.py` built its expected member list
  from *all* manifest rows while the archive builder correctly skips
  non-existent paths. Any dirty state containing a deletion or rename failed
  with zero missing files and zero hash mismatches — a verdict that said nothing.
- `boamp.synthetic.pipeline.generate_pilot` and `write_pilot_outputs` defaulted
  `benchmark_version` to `v0_1_provisional`, so an unqualified call silently
  wrote into a superseded directory.
- Notebooks 09, 10 and 11 had never been executed: zero stored outputs.
- Two `latexmk` byproducts sat in the repository root from a compile run in the
  wrong directory.

## 5. Is it reproducible?

Yes, under the pinned environment, and this is now checked rather than asserted.

| Check | Result |
|---|---|
| Fast test suite | 165 passed |
| Slow test suite | 11 passed — including the replay test that failed at the start |
| Central-world canonical replay | PASS, environment drift: none |
| All-artifact replay | PASS, 51/51 |
| Layer-1/Layer-2 parity vs frozen fingerprints | 9/9 pass |
| Interim corpus rebuilt from raw | byte-identical hash |
| Report consistency gate | PASS on all 8 checks |

The one caveat worth stating plainly: replay is bit-exact only under
`requirements-lock.txt`. Under a different NumPy build the counts, identities and
every reported statistic still reproduce, but the canonical SHA-256 will differ.
That is now detected and explained rather than mysterious.

## 6. Are the LaTeX and PDF consistent with the results?

Yes, and by construction rather than by inspection. The technical report contains
no hand-typed statistic: all 148 quoted values are macros generated from the
artifacts, and `scripts/check_report_consistency.py` fails the build if the
document and the artifacts disagree, if a macro is undefined, if a figure is
missing, if a numeric literal appears in the body, if the PDF is older than its
inputs, or if the LaTeX log carries an undefined reference or citation.

The three BOAMP layer reports still carry hand-typed numbers. Every one was
verified against the current tables (source counts, candidate pairs, links,
tiers, transitions, Fellegi–Sunter estimates, survival at 12 and 24 months,
RMST, hazard ratios, concordance) and all agree exactly. They were not converted
to the macro system; that remains open work.

## 7. Which benchmark properties are empirically supported

Estimated from observable real BOAMP, and reproduced within declared tolerances:
schema-family and notice-type composition, primary-department composition,
checksum-valid SIRET presence conditional on schema, year and notice type
(residuals within about 5 percentage points across all twelve years), CPV
missingness conditional on schema and notice type, duration presence and the
distribution of the *visible* declared duration, cross-buyer text reuse
conditional on notice type and buyer activity tier, and the per-source candidate
environment (zero-candidate rate 38.6% synthetic against 40.7% real).

Estimated through a documented proxy: buyer-name variation and ambiguity rates,
which use checksum-valid SIREN groupings where real buyer entities are not
observed.

## 8. Which properties remain scenario assumptions

True recurrence prevalence; the cycle-gap distribution; next-cycle text-drift
severity; the specific CPV corruption mode; the split of absent identifiers into
SIREN-only, invalid and fully missing; the call-to-award delay. None has an
empirical anchor anywhere in the corpus, all are labelled
`SCENARIO_UNIDENTIFIED` in the parameter registry, and none is quoted anywhere
as a measurement.

Separately, the five v0.3 scoped-candidate parameters were **tuned against
candidate-count fidelity gates**. They change linkage difficulty and are not
estimates of the real renewal process.

| # | Limitation | Severity | Why it is not fixed here |
|---|---|---|---|
